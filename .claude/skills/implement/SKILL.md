## 手順

1. 直前の `/plan` で合意した計画、または `$ARGUMENTS` で指定された内容に従って実装する
2. 実装ステップごとに以下を行う
   - 該当ファイルの作成・編集
   - CLAUDE.mdのコーディング規約に従っているか確認
   - ステップ完了時に進捗を報告
3. 全ステップ完了後、ビルド確認を行う
4. 変更内容のサマリーを提示する

## ビルド・テスト確認（実装完了後に必ず実施）

- 型チェック・ビルド確認は `build-runner` エージェントに委譲する（`npx tsc --noEmit` と `npm run build` を実行するだけの実行専用エージェント）
- E2Eテストの確認が必要な場合は `test-runner` エージェントに委譲する（`npm run test:e2e` を実行するだけの実行専用エージェント）
- これらのエージェントは実行と結果報告のみを行う。エラーが報告された場合の原因調査・修正はメイン側（自分）が行う
- 直接 `npm run build` / `npx tsc` / `npm run test:e2e` をBashで実行しない。冗長な出力（変換モジュール数、全テストケース名など）がメインセッションの会話履歴に残り続け、トークンを消費するため
- ビルドエラーがあれば修正し、`build-runner` に再確認させてから完了とする

## コーディング規約の確認ポイント

- フロントエンド: `any` を使っていないか、型定義が `types/` に切り出されているか
- GAS: `var` を使っていないか、スプレッドシート操作が一括処理になっているか
- 共通: エラーが握りつぶされていないか

## 注意

- 実装中にコミットは行わない（ユーザーの確認後にコミットする）
- 計画にない変更やリファクタリングは行わない
- 判断に迷う箇所があればユーザーに確認する
